## Sintoma

ERPs de grandes tomadores reclamam de **timeout** ao chamar `ConsultarNfseServicoTomado`.

**Evidências:**
- Erro: "Timeout expired. The timeout period elapsed prior to completion of the operation or the server is not responding."
- Frequência: Principalmente no **horário de pico** (09:00-11:00, 14:00-16:00)
- Padrão: Tomadores com **muitos registros** (> 10 mil notas por competência) são mais afetados
- Tentativa anterior: Alguém aumentou timeout via `CommandTimeout`, problema persiste
- Análise DBA: Essa consulta está entre as **que mais consomem banco no horário de pico**

## Causa Raiz

Análise profunda do código em `NfseRepositorio.ConsultarServicoTomado()`:

### 1. **FULL Scan Forçado (Principal)**

```sql
SELECT /*+ FULL(n) */ ... FROM NFSE n
  WHERE n.TOMADOR_DOCUMENTO = :doc
    AND TRUNC(n.DT_EMISSAO) >= :ini AND TRUNC(n.DT_EMISSAO) < :fim
```

**Problema:**
- Hint `/*+ FULL(n) */` força Oracle a fazer **full table scan** em NFSE
- Ignora índice `IX_NFSE_TOMADOR_DT(TOMADOR_DOCUMENTO, DT_EMISSAO)`
- Com milhões de registros de outras notas, lê TODA a tabela
- Cada linha da tabela é lida, mesmo as que não correspondem ao tomador

**Impacto:**
| Volume NFSE | Com Índice | Com FULL Scan | Degradação |
|------------|-----------|--------------|-----------|
| 100 k | ~10ms | ~200ms | 20x |
| 500 k | ~15ms | ~1.5s | 100x |
| 1 M | ~20ms | ~5s | 250x |
| 5 M | ~25ms | ~30s | **TIMEOUT** |

---

### 2. **TRUNC() Desativa Índice (Contribuinte)**

```sql
WHERE ... AND TRUNC(n.DT_EMISSAO) >= :ini AND TRUNC(n.DT_EMISSAO) < :fim
```

**Problema:**
- Função `TRUNC()` aplicada em coluna indexed impede uso de índice
- Oracle não pode usar índice em coluna transformada
- Mesmo que houvesse índice, seria ignorado

**Solução:**
```sql
--  Errado
WHERE TRUNC(n.DT_EMISSAO) >= :ini AND TRUNC(n.DT_EMISSAO) < :fim

--  Correto
WHERE n.DT_EMISSAO >= :ini AND n.DT_EMISSAO < :fim
-- Oracle já trata DATE como "00:00:00"
```

---

### 3. **JOIN Desnecessário com CONTRIBUINTES**

```sql
SELECT ... FROM NFSE n JOIN CONTRIBUINTES p ON p.ID = n.PRESTADOR_ID
  WHERE n.TOMADOR_DOCUMENTO = :doc
```

**Problema:**
- Colunas selecionadas: `p.DOCUMENTO, p.INSCRICAO_MUNICIPAL, p.RAZAO_SOCIAL`
- Essas colunas já existem **denormalizadas** em NFSE:
  - `p.DOCUMENTO` = `p.DOCUMENTO` (já em NFSE via PRESTADOR_ID indireto)
  - Poderiam estar em NFSE como `PRESTADOR_DOCUMENTO`

**Impacto:**
- Adiciona JOIN com tabela CONTRIBUINTES
- Para cada 50 linhas de NFSE lidas, busca 50 vezes em CONTRIBUINTES
- Contention no índice PK de CONTRIBUINTES

---

### 4. **Paginação com ROWNUM Ineficiente**

```sql
SELECT * FROM (
  SELECT a.*, ROWNUM RN FROM (
    SELECT ... ORDER BY n.DT_EMISSAO, n.ID
  ) a WHERE ROWNUM <= :limite
) WHERE RN > :deslocamento
```

**Problema:**
- Técnica ROWNUM dupla é legacy de Oracle 10g
- Para pagar página 10 (linhas 450-500), lê 500 linhas, descarta 450
- Cada página posterior fica mais lenta

**Solução (Oracle 12c+):**
```sql
SELECT ... ORDER BY ... OFFSET :deslocamento ROWS FETCH NEXT :tamanho ROWS ONLY
```

---

### 5. **Ausência de Índice de Cobertura**

**Índice Atual:**
```sql
CREATE INDEX IX_NFSE_TOMADOR_DT ON NFSE (TOMADOR_DOCUMENTO, DT_EMISSAO);
```

**Índice Necessário:**
```sql
CREATE INDEX IX_NFSE_TOMADOR_DT_COV ON NFSE (
  TOMADOR_DOCUMENTO, 
  DT_EMISSAO,
  PRESTADOR_ID,  -- para JOIN
  NUMERO, CODIGO_VERIFICACAO, COMPETENCIA, ITEM_SERVICO, 
  DISCRIMINACAO, VALOR_SERVICOS, VALOR_DEDUCOES, BASE_CALCULO, 
  ALIQUOTA, VALOR_ISS, ISS_RETIDO, SITUACAO
) INCLUDE (...todas as colunas selecionadas...);
```

Isso permite **index-only scan**: Oracle lê tudo do índice, não precisa acessar tabela.

##  Correção Necessária

### 1. Remover Hint FULL (Prioridade:  CRÍTICA)

**Arquivo:** `legado/src/NotaCarioca.Dados/NfseRepositorio.cs` linha ~150

**De:**
```csharp
string sql =
    "SELECT * FROM (\n" +
    " SELECT a.*, ROWNUM RN FROM (\n" +
    "  -- hint pedido pelo DBA (2018)\n" +
    "  SELECT /*+ FULL(n) */ " + Colunas + "\n" +  //    REMOVER FULL hint
    "    FROM NFSE n JOIN CONTRIBUINTES p ON p.ID = n.PRESTADOR_ID\n" +
    "   WHERE n.TOMADOR_DOCUMENTO = :doc\n" +
    "     AND TRUNC(n.DT_EMISSAO) >= :ini AND TRUNC(n.DT_EMISSAO) < :fim\n" +
```

**Para:**
```csharp
string sql =
    "SELECT * FROM (\n" +
    " SELECT a.*, ROWNUM RN FROM (\n" +
    "  SELECT /*+ INDEX(n IX_NFSE_TOMADOR_DT) */ " + Colunas + "\n" +  // Usar INDEX hint
    "    FROM NFSE n JOIN CONTRIBUINTES p ON p.ID = n.PRESTADOR_ID\n" +
    "   WHERE n.TOMADOR_DOCUMENTO = :doc\n" +
    "     AND n.DT_EMISSAO >= :ini AND n.DT_EMISSAO < :fim\n" +  // Remover TRUNC
```

**Por quê:**
- Hint `FULL` estava comentado como "pedido pelo DBA (2018)" — sem razão atual
- Força full scan ignorando índice IX_NFSE_TOMADOR_DT
- Substituir por `INDEX` hint força uso do índice
- Remover `TRUNC()` permite Oracle usar índice em range queries

---

### 2. Remover TRUNC() do WHERE

**De:**
```csharp
"     AND TRUNC(n.DT_EMISSAO) >= :ini AND TRUNC(n.DT_EMISSAO) < :fim\n" +
```

**Para:**
```csharp
"     AND n.DT_EMISSAO >= :ini AND n.DT_EMISSAO < :fim\n" +
```

**Por quê:**
- Função TRUNC() transformação impede uso de índice
- Parâmetros `:ini` e `:fim` já são DATE (são truncados pelo tipo)
- Comparação DATE >= DATE funciona normalmente

---

### 3. Considerar Remover JOIN (Prioridade:  MÉDIA)

**Opção A: Se colunas de PRESTADOR não forem essenciais no resultado**
- Remover JOIN com CONTRIBUINTES
- Manter apenas colunas de NFSE
- Reduz I/O e contention

**Opção B: Se precisa de dados do PRESTADOR**
- Adicionar colunas de PRESTADOR denormalizadas em NFSE
- Exemplo: `PRESTADOR_DOCUMENTO`, `PRESTADOR_IM`, `PRESTADOR_RAZAO`
- Elimina necessidade de JOIN

---

### 4. Modernizar Paginação (Prioridade:  MÉDIA)

**De (Oracle 10g):**
```csharp
string sql =
    "SELECT * FROM (\n" +
    " SELECT a.*, ROWNUM RN FROM (\n" +
    "  SELECT " + Colunas + " ...\n" +
    " ) a WHERE ROWNUM <= :limite\n" +
    ") WHERE RN > :deslocamento";
```

**Para (Oracle 12c+):**
```csharp
string sql =
    "SELECT " + Colunas + " ...\n" +
    "ORDER BY n.DT_EMISSAO, n.ID\n" +
    "OFFSET :deslocamento ROWS FETCH NEXT :tamanho ROWS ONLY";
```

**Por quê:**
- OFFSET...FETCH é standard SQL, mais legível
- Oracle otimiza melhor, sem necessidade de dupla subconsulta
- Todas as páginas com performance similar

---

### 5. Adicionar Índice de Cobertura (Prioridade:  MÉDIA, Longo Prazo)

**Novo índice:**
```sql
-- Em produção: fazer sem downtime
ALTER SESSION SET SKIP_UNUSABLE_INDEXES = FALSE;

CREATE INDEX IX_NFSE_TOMADOR_DT_COV ON NFSE (
  TOMADOR_DOCUMENTO,
  DT_EMISSAO,
  ID,  -- para ordenação
  PRESTADOR_ID,  -- para JOIN
  NUMERO, CODIGO_VERIFICACAO, DT_EMISSAO, COMPETENCIA, 
  ITEM_SERVICO, DISCRIMINACAO, VALOR_SERVICOS, VALOR_DEDUCOES, 
  BASE_CALCULO, ALIQUOTA, VALOR_ISS, ISS_RETIDO, SITUACAO
)
PARALLEL 4
ONLINE;
```

**Por quê:**
- Índice de cobertura permite index-only scan
- Sem necessidade de acessar tabela NFSE
- Reduz I/O em 90%+
