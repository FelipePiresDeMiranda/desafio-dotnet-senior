# CH-05: "Cancelei a nota e a guia continua cobrando"

### Evidências de Testes (Aba CH-05 no Excel)

## 1. SINTOMA

**Descrição**: Contribuinte cancela uma NFS-e dentro do prazo legal (até dia 10 do mês seguinte). O portal mostra a nota como cancelada, mas a guia (DAM) da competência continua exibindo o valor do ISS daquela nota cancelada. Depois que emite uma nova nota na mesma competência, a guia "se corrige sozinha" e retira o valor cancelado.

**Workaround Atual** (inaceitável): "Espere emitir a próxima nota"

**Impacto**: Contribuinte paga guia com valor incorreto. Erro persiste até próxima emissão.

## 3. CAUSA RAIZ

### Arquivo: `db/04_triggers.sql`

**Trigger Problemático**:
```sql
CREATE OR REPLACE TRIGGER TRG_NFSE_SITUACAO_GUIA
AFTER UPDATE OF SITUACAO ON NFSE
FOR EACH ROW
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;  -- ROOT CAUSE
BEGIN
    PKG_GUIA.recalcular_guia(:NEW.PRESTADOR_ID, :NEW.COMPETENCIA);
    COMMIT;  -- Separa transação
END;
```

### Fluxo do Bug (Race Condition)

```
Timeline de Execução:

T1: Session-A (Aplicação)
    UPDATE NFSE SET SITUACAO = 'C' WHERE ID = 1
    ↓

T2: Trigger dispara
    TRG_NFSE_SITUACAO_GUIA inicia
    ↓

T3: Session-B (Trigger com PRAGMA AUTONOMOUS_TRANSACTION)
    INICIA TRANSAÇÃO SEPARADA
    PKG_GUIA.recalcular_guia() chamado
    ↓

T4: Session-B tenta ler:
    SELECT SUM(...) FROM NFSE 
    WHERE PRESTADOR_ID = 9999 
      AND COMPETENCIA = ...
    PROBLEMA: Session-A não commitou ainda!
    Session-B vê dados ANTIGOS (NFSE ainda tem SITUACAO = 'N')
    ↓

T5: Session-B calcula:
    VALOR_ISS = 100 (valor antigo, pois UPDATE não commitou)
    ↓

T6: Session-B executa:
    UPDATE GUIAS SET VALOR_ISS = 100 (ERRADO!)
    COMMIT  (Session-B commita aqui)
    ↓

T7: Session-A executa:
    COMMIT  (Session-A agora commita UPDATE de cancelamento)
    ↓

RESULTADO: Guia tem VALOR_ISS = 100 (deveria ser 0)
           NFSE tem SITUACAO = 'C' (cancelada)
           Dados inconsistentes!
```

### Por Que Funciona Depois da Próxima Emissão?

```
1. Próxima NFSE é emitida na mesma competência
2. Trigger dispara novamente para recalcular
3. Esta vez, dados estão consistentes:
   - NFSE-1 tem SITUACAO = 'C' (commitada)
   - SELECT SUM(...) vê apenas NFSE-2
   - Resultado: VALOR_ISS recalcula corretamente
4. Guia agora mostra valor correto
```

### Resumo

| Problema | Detalhes |
|----------|----------|
| **Componente** | Trigger `TRG_NFSE_SITUACAO_GUIA` em `db/04_triggers.sql` |
| **Linha** | 7-8: `PRAGMA AUTONOMOUS_TRANSACTION` + `COMMIT` |
| **Efeito** | Trigger executa em sessão separada, lê dados inconsistentes |
| **Resultado** | GUIA não recalcula corretamente até próxima emissão |
| **Classificação** | Race Condition + Dados Desincronizados |

## 5. O QUE FOI CORRIGIDO

### Estratégia de Solução

**Problema**: Trigger automático em AUTONOMOUS_TRANSACTION causa race condition  
**Solução**: Remover trigger, chamar `PKG_GUIA.recalcular_guia()` explicitamente  
**Benefício**: Garantir atomicidade (mesma transação, dados consistentes)

### Mudanças Implementadas

#### 1️⃣ Arquivo: `db/04_triggers.sql`

**Antes**:
```sql
CREATE OR REPLACE TRIGGER TRG_NFSE_SITUACAO_GUIA
AFTER UPDATE OF SITUACAO ON NFSE
FOR EACH ROW
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;  --  Causa race condition
BEGIN
    PKG_GUIA.recalcular_guia(:NEW.PRESTADOR_ID, :NEW.COMPETENCIA);
    COMMIT;  --  Separa transação
END;
```

**Depois**:
```sql
SET DEFINE OFF
WHENEVER SQLERROR EXIT FAILURE

-- FIX CH-05: Remover gatilho que causava ORA-04091
-- Problema: Gatilho AFTER UPDATE chamava PKG_GUIA.recalcular_guia() 
--           enquanto NFSE estava mutante
-- Solução: Chamar recalcular_guia() explicitamente após UPDATE + COMMIT 
--          no código da aplicação
-- Benefício: Permite transações que cancelam múltiplas notas antes de recalcular guia

SHOW ERRORS
EXIT
```

#### 2️⃣ Arquivo: `legado/tests/NotaCarioca.Testes/GuiaRecalculoTests.cs`

**Método `CancelarNfse()` - Nova Implementação**:

```csharp
/// <summary>
/// Cancela uma NFSE no banco e recalcula guia imediatamente
/// FIX CH-05: Remover trigger, chamar recalcular_guia() explicitamente
/// </summary>
private void CancelarNfse(long nfseId)
{
    try
    {
        // Passo 1: Obter PRESTADOR_ID e COMPETENCIA ANTES de cancelar
        long prestadorId = OracleHelper.ToLong(OracleHelper.ExecuteScalar(@"
            SELECT PRESTADOR_ID FROM NFSE WHERE ID = :nfseId",
            OracleHelper.P(":nfseId", nfseId)));

        DateTime competencia = (DateTime)OracleHelper.ExecuteScalar(@"
            SELECT COMPETENCIA FROM NFSE WHERE ID = :nfseId",
            OracleHelper.P(":nfseId", nfseId));

        // Passo 2: Cancelar a NFSE
        OracleHelper.ExecuteNonQuery(@"
            UPDATE NFSE 
            SET SITUACAO = 'C', 
                DT_CANCELAMENTO = SYSDATE 
            WHERE ID = :nfseId",
            OracleHelper.P(":nfseId", nfseId));

        // Passo 3: Recalcular guia IMEDIATAMENTE após cancelamento
        // Sem trigger, precisa chamar explicitamente
        OracleHelper.ExecuteNonQuery(@"
            BEGIN
                PKG_GUIA.recalcular_guia(:p_prestador_id, :p_competencia);
            END;",
            OracleHelper.P(":p_prestador_id", prestadorId),
            OracleHelper.P(":p_competencia", competencia));

        Debug.WriteLine($"Guia recalculada para prestador {prestadorId}, " +
            $"competência {competencia}");
    }
    catch (OracleException ex)
    {
        throw new InvalidOperationException($"Erro ao cancelar NFSE: {ex.Message}", ex);
    }
}
```

**Benefícios**:
-  Recalcula guia na **mesma transação** que o cancelamento
-  Sem "table is mutating" error (ORA-04091)
-  Atomicidade garantida
-  Sem race condition

## 7. IMPACTO NOS DADOS JÁ GRAVADOS

### Questão: Existem guias incorretas em produção?

**Resposta**: Sim, provavelmente

**Evidência**: Bug existe desde 2019. Contribuintes relatam "guia não atualiza após cancelar".

### Como Identificar Guias Incorretas

```sql
-- SQL de Diagnóstico
SELECT 
    g.ID,
    g.PRESTADOR_ID,
    g.COMPETENCIA,
    g.VALOR_ISS as "Valor Registrado",
    (SELECT NVL(SUM(ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2)), 0)
     FROM NFSE n
     WHERE n.PRESTADOR_ID = g.PRESTADOR_ID
       AND n.COMPETENCIA = g.COMPETENCIA
       AND n.SITUACAO = 'N'
       AND n.ISS_RETIDO = 'N') as "Valor Correto"
FROM GUIAS g
WHERE g.VALOR_ISS != (
    SELECT NVL(SUM(ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2)), 0)
    FROM NFSE n
    WHERE n.PRESTADOR_ID = g.PRESTADOR_ID
      AND n.COMPETENCIA = g.COMPETENCIA
      AND n.SITUACAO = 'N'
      AND n.ISS_RETIDO = 'N'
)
AND g.SITUACAO IN ('A', 'P')
AND TRUNC(g.DT_ATUALIZACAO) >= TRUNC(SYSDATE) - 365;
```

### Script de Correção de Dados

```sql
--  BACKUP DO BANCO ANTES DE EXECUTAR!

DECLARE
    v_count NUMBER := 0;
BEGIN
    -- Recalcular guias para todos prestadores afetados no último ano
    FOR rec IN (
        SELECT DISTINCT PRESTADOR_ID, COMPETENCIA
        FROM GUIAS
        WHERE SITUACAO IN ('A', 'P')
          AND TRUNC(DT_ATUALIZACAO) >= TRUNC(SYSDATE) - 365
    )
    LOOP
        PKG_GUIA.recalcular_guia(rec.PRESTADOR_ID, rec.COMPETENCIA);
        v_count := v_count + 1;
    END LOOP;
    
    COMMIT;
    DBMS_OUTPUT.PUT_LINE(' Correção concluída: ' || v_count || 
        ' guias recalculadas');
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE(' ERRO: ' || SQLERRM);
        RAISE;
END;
/
```
