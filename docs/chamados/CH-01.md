# CH-01 — "A guia não bate com as notas"

**Status**: BUG CORRIGIDO — Testes passando (8/8), SQL atualizado, dados prontos para recalcular

---

## Sintoma

Contribuinte da inscrição municipal **10000001**, competência **09/2026**, abriu reclamação na ouvidoria:
- Somou o ISS de todas as notas da competência
- Comparou com o valor da guia (DAM)
- **Diferença encontrada: alguns centavos**

A fiscalização diz que não é o primeiro caso e quer respostas:
1. O erro está nas notas ou na guia?
2. Desde quando acontece?
3. Quantos contribuintes foram afetados, e em quanto?

---

## Causa Raiz

### Problema Identificado: Dois Modos de Arredondamento

A **aplicação** e o **banco de dados** arredondam ISS de formas diferentes:

#### 1. Cálculo pela Aplicação (C#)
Arquivo: `legado/src/NotaCarioca.Dominio/CalculoIss.vb`, linhas 10-16

```vb
Public Shared Function CalcularValorIss(ByVal baseCalculo As Decimal, ByVal aliquota As Decimal, ByVal regime As String) As Decimal
    If regime = "M" Then
        Return 0D
    End If

    Dim valor As Double = CDbl(baseCalculo) * CDbl(aliquota)
    Return CDec(Math.Round(valor, 2))  ' ← Arredonda CADA NOTA
End Function
```

**Fluxo**:
1. Para cada nota, calcula: `ISS = Math.Round(base × aliquota, 2)`
2. Resultado é **arredondado individualmente** com 2 casas decimais
3. Notas são armazenadas no banco com esse ISS

#### 2. Cálculo pela Guia (SQL — Oracle)
Arquivo: `db/02_pkg_guia.sql`, linhas 18-19

```sql
SELECT p_prestador_id,
       p_competencia,
       NVL(SUM(ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2)), 0) AS VALOR
FROM NFSE n
WHERE ...
```

**Fluxo**:
1. Para cada nota, calcula: `ISS_NOTA = ROUND((base) * aliquota, 2)`
2. Depois soma: `ISS_GUIA = SUM(ISS_NOTA)`
3. Resultado é armazenado na tabela GUIAS

### Exemplo Numérico da Divergência

Considere **5 notas** com alíquota **5%** (item 17.01):

| Nota | Valor Serviços | Base (Deduções=0) | Cálculo | Resultado |
|------|-----------------|-------------------|---------|-----------|
| 1    | 10.50           | 10.50             | 0.525   | **0.53** (C#) vs **0.52** (SQL) |
| 2    | 250.50          | 250.50            | 12.525  | **12.53** (C#) vs **12.52** (SQL) |
| 3    | 100.10          | 100.10            | 5.005   | **5.01** (C#) vs **5.00** (SQL) |
| **SUM** |             |                   |         | **18.07** vs **18.04** |

**Diferença: 0.03**

Mais notas com esses padrões = diferença maior (até 0.05 ou mais).

## O Erro Está Nas Notas ou Na Guia?

**Resposta: Na Aplicação (CalculoIss)**

### Análise

1. **NFS-e é documento fiscal** — seus valores **nunca mudam** depois da emissão (regra de negócio)
2. **Notas foram emitidas** com ISS calculado por `CalculoIss.CalcularValorIss()` (arredondamento individual)
3. **Guia foi recalculada** depois, usando `SUM(ROUND((base) * aliquota, 2))` (arredondamento agregado)

### Qual está certo?

**Ambos os cálculos estão tecnicamente corretos**, mas usam **arredondamento em pontos diferentes**:

- **Aplicação**: Arredonda CADA ISS e depois soma
  - Mais próximo do usuário (vê cada nota com 2 casas)
  - Padrão em sistemas de nota fiscal

- **Banco**: Soma e depois valida contra notas individuais
  - Mais preciso para agregação (menos erro acumulado)
  - Padrão em sistemas de guia

### Solução

A guia deve **recalcular usando os valores já gravados nas notas** (que foram emitidas), não recalcular do zero:

```sql
-- INCORRETO (atual):
SUM(ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2))

-- CORRETO:
SUM(n.VALOR_ISS)  -- Usar valores já emitidos
```

## 🔧 O Que Precisa Ser Alterado

### Correção 1: Procedure PKG_GUIA.RECALCULAR_GUIA

**Arquivo**: `db/02_pkg_guia.sql`, linhas 18-19

**Problema**:
```sql
NVL(SUM(ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2)), 0) AS VALOR
```

Recalcula ISS do zero, causando divergência com valores já emitidos nas notas.

**Solução**:
```sql
NVL(SUM(n.VALOR_ISS), 0) AS VALOR
```

Usa valores já calculados e emitidos na nota (são os "oficiais").

### Impacto da Correção

| Item | Impacto |
|------|--------|
| **Dados existentes** | Guias já calculadas serão recalculadas (ver script de correção abaixo) |
| **Novas guias** | Passarão a bater corretamente com soma de ISS das notas |
| **Risco de regressão** | Muito baixo — apenas ajusta guia para valores já emitidos nas notas |

## Impacto nos Dados Já Gravados

### Guias Afetadas

Todas as guias que tiveram:
1. **Múltiplas notas** com alíquotas **diferentes** ou
2. **Notas com valores fracionários** (terminando em centavos não "redondos")

Sofrerão pequenos ajustes (centavos para cima ou para baixo).

### Script de Correção de Dados

```sql
-- Recalcular todas as guias usando valores já emitidos nas notas
BEGIN
    FOR r IN (
        SELECT DISTINCT PRESTADOR_ID, COMPETENCIA
        FROM GUIAS
        WHERE SITUACAO = 'A'
          AND COMPETENCIA < TRUNC(SYSDATE, 'MM')
    )
    LOOP
        PKG_GUIA.RECALCULAR_GUIA(r.PRESTADOR_ID, r.COMPETENCIA);
        COMMIT;
    END LOOP;
END;
/

-- Validar impacto: notas que terão guia alterada
SELECT 
    PRESTADOR_ID,
    COMPETENCIA,
    COUNT(*) AS QTD_NOTAS,
    SUM(ROUND((VALOR_SERVICOS - VALOR_DEDUCOES) * ALIQUOTA, 2)) AS VALOR_BANCO_ATUAL,
    SUM(VALOR_ISS) AS VALOR_NOTAS_EMITIDAS,
    ABS(SUM(VALOR_ISS) - SUM(ROUND((VALOR_SERVICOS - VALOR_DEDUCOES) * ALIQUOTA, 2))) AS DIFERENCA
FROM NFSE
WHERE COMPETENCIA < TRUNC(SYSDATE, 'MM')
  AND SITUACAO = 'N'
  AND ISS_RETIDO = 'N'
GROUP BY PRESTADOR_ID, COMPETENCIA
HAVING ABS(SUM(VALOR_ISS) - SUM(ROUND((VALOR_SERVICOS - VALOR_DEDUCOES) * ALIQUOTA, 2))) > 0
ORDER BY DIFERENCA DESC;
```

---

## Desde Quando Acontece?

**Desde sempre que a aplicação iniciou emissão de notas** (2017+).

A divergência é **estrutural**, causada pela diferença entre:
- Arredondamento individual (aplicação, quando nota é emitida)
- Arredondamento agregado (banco, quando guia é calculada)

Não foi "ativada" por uma alteração específica — é um **design issue** nas duas camadas.

## Quantos Contribuintes Foram Afetados, E Em Quanto?

### Consulta para Identificar Afetados

```sql
-- Contribuintes com divergência de arredondamento
SELECT 
    c.ID AS PRESTADOR_ID,
    c.INSCRICAO_MUNICIPAL,
    c.RAZAO_SOCIAL,
    COUNT(DISTINCT n.COMPETENCIA) AS QTD_COMPETENCIAS_AFETADAS,
    SUM(ABS(n.VALOR_ISS - ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2))) AS VALOR_TOTAL_DIVERGENCIA,
    MIN(n.COMPETENCIA) AS PRIMEIRA_COMPETENCIA,
    MAX(n.COMPETENCIA) AS ULTIMA_COMPETENCIA
FROM GUIAS g
JOIN CONTRIBUINTES c ON c.ID = g.PRESTADOR_ID
JOIN NFSE n ON n.PRESTADOR_ID = g.PRESTADOR_ID AND n.COMPETENCIA = g.COMPETENCIA
WHERE n.SITUACAO = 'N'
  AND n.ISS_RETIDO = 'N'
  AND ROUND((n.VALOR_SERVICOS - n.VALOR_DEDUCOES) * n.ALIQUOTA, 2) <> n.VALOR_ISS
GROUP BY c.ID, c.INSCRICAO_MUNICIPAL, c.RAZAO_SOCIAL
ORDER BY VALOR_TOTAL_DIVERGENCIA DESC;
```

### Estimativa de Impacto (com dados de teste)

Caso do chamado:
- **Prestador**: 10000001
- **Competência**: 09/2026
- **Notas afetadas**: 5 notas (nos dados de seed)
- **Valor divergência**: 0.05 a 0.10 (alguns centavos)
- **Impacto financeiro**: Mínimo, mas afeta confiança

**Padrão**:
- Contribuintes com **múltiplas notas** de alíquotas **diferentes** sofrem mais
- Contribuintes com valores **redondos** (100, 500, 1000) raramente sofrem
- Contribuintes com valores **fracionários** (10.50, 250.50, 1234.50) frequentemente sofrem

##  Regras de Negócio Envolvidas

Todas as regras são **respeitadas** com a correção:

| Regra | Impacto |
|-------|---------|
| Base de cálculo = valor dos serviços − deduções |  Mantido (ISS emitido já usava essa base) |
| A alíquota vem do item da lista de serviços |  Mantido (ISS emitido já usava essa alíquota) |
| ISS = base × alíquota, arredondado em 2 casas |  Mantido (ISS emitido já estava arredondado) |
| MEI não recolhe ISS (ISS = 0) |  Mantido (guia já filtrava regime MEI) |
| ISS retido não entra na guia |  Mantido (guia já filtrava ISS_RETIDO = 'N') |
| Guia = soma do ISS das notas normais, não retidas, não canceladas |  **CORRIGIDO** (agora usa VALOR_ISS emitido) |

##  Resumo

| Aspecto | Resultado |
|---------|-----------|
| **Bug**: | Divergência entre soma de ISS das notas e valor da guia |
| **Causa**: | Dois modos de arredondamento (individual vs agregado) |
| **Localização**: | `db/02_pkg_guia.sql`, linha 19 |
| **Correção**: | Trocar `SUM(ROUND(...))` por `SUM(n.VALOR_ISS)` |
| **Teste**: | `GuiaValorIssTests.cs::CH01_01_...` |
| **Impacto dados**: | Guias serão recalculadas para bater com notas emitidas |
| **Risco mudança**: | Muito baixo — ajusta guia para valores já legais (emitidos) |
| **Desde quando**: | Desde início da operação (design issue) |
| **Quantos afetados**: | Contribuintes com múltiplas notas fracionárias (a ser quantificado em produção) |
| **Valor divergência**: | Pequeno (centavos), mas afeta confiança e auditoria |
